# 805 宿舍电量分析与微信公众号 H5 设计

## 1. 背景与目标

本项目面向麒麟科创园 7 号楼 8F 805 房间。物业及开发方已明确授权接口抓取、接口分析和数据接入。

系统长期运行在公网服务器上，每 30 分钟从物业接口同步一次电费数据，形成用电趋势、费用趋势、峰值时段、异常用电和余额可用天数分析，并通过微信公众号自定义菜单打开移动端 H5 页面。

系统只服务当前房间，不建设多住户平台，不提供充值、支付或修改物业数据的能力。

## 2. 已有源码评估

参考源码归档为 `C:\Users\zdht\Desktop\my_eletricity_web.tar.gz`，包含一个 Flask 原型和一个 ECharts 页面。

原型已经确认以下服务端接口模式：

- 使用账号密码请求 `/xboot/auth/login`，成功后取得 `Accesstoken`。
- 使用 `Accesstoken` 请求 `/xboot/goodits/room/pageBalanceDetails`。
- 通过日期、分页和 `type=2` 查询电费明细。
- Token 失效后可再次使用账号密码登录。

原型只能作为接口连接方式的参考，不能直接部署，原因包括：

- 关闭 HTTPS 证书验证。
- 凭证硬编码，Token 使用明文文件缓存。
- Flask 调试服务器直接监听公网。
- 页面和数据接口无访问控制。
- 没有数据库、定时采集、公众号 OAuth、可靠日志和故障告警。
- H5 文件存在编码损坏和 JavaScript 语法问题。
- 半小时时间取整可能覆盖同一时间窗口内的多条记录。

## 3. 范围

### 3.1 首版包含

- 物业接口连接、登录、Token 自动续期和只读数据采集。
- 每 30 分钟同步当日和前一日的电费数据。
- SQLite 原始记录、汇总结果和同步状态存储。
- 24 小时、7 天、30 天用电与费用分析。
- 日均、峰值时段、对比、异常和余额可用天数预测。
- 微信公众号 `snsapi_userinfo` OAuth。
- 指定 `openid` 白名单。
- 微信内移动端 H5 仪表盘。
- Ubuntu 24.04、Nginx、HTTPS 和 systemd 部署。
- 数据备份、日志脱敏、健康状态和认证失效提示。

### 3.2 首版不包含

- 多住户注册或多租户隔离。
- 充值、支付、退款或物业数据写入。
- 公众号主动消息推送。
- 自动操作微信客户端。
- 绕过微信登录、证书校验或物业权限控制。

## 4. 总体架构

服务器运行一个轻量级 Python 系统：

1. **物业连接器**：封装登录、Token、分页、超时、证书校验和错误映射。
2. **采集任务**：每 30 分钟同步数据，并每日修正最近 30 天汇总。
3. **SQLite 数据库**：保存原始记录、分析汇总、同步状态和访问白名单。
4. **分析服务**：按半小时、小时、日和月生成指标。
5. **FastAPI Web 服务**：提供 OAuth 入口、H5 页面和受保护的数据 API。
6. **微信公众号适配器**：完成 OAuth 回调和 `openid` 白名单检查。
7. **Nginx**：提供 HTTPS、限流、静态资源和反向代理。
8. **systemd**：管理应用进程、开机启动和异常重启。

应用只监听 `127.0.0.1`。Nginx 是唯一公网入口。SQLite 文件、管理命令和物业连接器均不暴露公网。

## 5. 数据采集

### 5.1 同步流程

1. 调度器每 30 分钟启动一次同步。
2. 连接器使用当前 Token 请求当天电费明细。
3. 若认证失败，使用账号密码重新登录并重试一次。
4. 同步前一天数据，吸收跨日或延迟入账记录。
5. 在数据库事务中执行去重插入或更新。
6. 更新本次同步时间、状态、记录数和错误摘要。
7. 触发当天及受影响日期的分析重算。

每天凌晨额外拉取并重新汇总最近 30 天数据，修正物业接口可能发生的历史调整。

### 5.2 去重与原始数据

优先使用物业返回的稳定记录 ID。若接口没有稳定 ID，则以设备标识、记录时间、用量、金额和费率生成确定性哈希作为唯一键。

原始时间、原始用量、原始金额和原始响应中的必要业务字段必须保留。分析层再按时间窗口聚合，不在采集阶段取整或覆盖原始记录。

### 5.3 分页

连接器按接口返回的总数或是否还有下一页持续分页，不能依赖固定的 `pageSize=100` 假定。对每次同步设置最大页数保护，超过上限时记为不完整同步且不覆盖已有完整汇总。

### 6.2 `daily_summaries`

- 记录数量

- 峰值发生时间
- 日均基线

### 6.3 `balance_snapshots`

## 7. 分析指标

首版计算：

- 今日、近 24 小时、7 天、30 天总用电量和总费用。
- 日均用电和日均费用。
- 最高用电日、半小时峰值及其时间。
- 按小时聚合的典型高峰时段。
- 今日与昨日、今日与近 7 日均值的变化率。
- 基于近期滚动窗口的异常升高。
- 夜间或指定低活动时段的持续耗电异常。
- 根据近期日均费用估算电费余额可用天数。
- 最后成功同步时间、数据新鲜度和采集健康状态。

当样本不足时，不输出误导性的预测值，而是标记“数据不足”。余额小于或等于零时直接显示余额告警，不计算正向可用天数。

## 8. 微信公众号接入

公众号自定义菜单指向部署时配置的正式 HTTPS 域名，其固定路径为 `/wechat/entry`。

流程：

1. `/wechat/entry` 生成 OAuth `state` 并跳转微信授权地址。
2. 使用 `snsapi_userinfo` 授权获取 `openid`；测试公众号会显示用户确认页。
3. `/wechat/callback` 校验 `state`、交换授权结果并检查白名单。
4. 通过白名单后创建短期登录会话。
5. H5 和数据 API 均校验会话。

系统不读取微信头像、昵称或联系人。未授权账号只返回通用无权限页面，不返回房间、余额、接口状态或其他业务信息。

域名实名、备案、解析和 HTTPS 完成前，仅通过 SSH 端口转发进行测试，不直接通过公网 IP 暴露住户数据页面。

## 9. H5 页面

移动端单页仪表盘包含：

- 当前电费余额。
- 今日用电与今日费用。
- 预计余额可用天数。
- 最后更新时间和采集状态。
- 24 小时、7 天、30 天趋势切换。
- 今日与昨日、近 7 日均值对比。
- 按小时用电分布和峰值时段。
- 异常用电提示。
- 按日期查询半小时明细。

数据超过 90 分钟未成功更新时，页面明确显示数据过期提示，同时保留历史数据查看能力。

## 10. 安全设计

- 物业账号密码、公众号 AppID、公众号 AppSecret、应用会话密钥通过服务器环境文件提供。
- 环境文件仅应用服务账号可读，不进入 Git。
- 不再使用明文 `token_cache.txt`；Token 只存储在受限配置或数据库加密字段中。
- 物业请求恢复 HTTPS 证书校验，设置连接和读取超时。
- 若上游使用非标准证书链，只部署经物业方确认的专用 CA，不使用 `verify=False`。
- 日志遮蔽密码、Token、Cookie、OAuth code、`openid` 和上游敏感字段。
- 所有 H5 数据 API 均需要登录会话和白名单授权。
- OAuth `state` 防重放，会话 Cookie 设置 `Secure`、`HttpOnly` 和适当的 `SameSite`。
- Nginx 对 OAuth 和数据 API 设置限流与安全响应头。
- 不提供公网凭证修改接口。凭证更新通过服务器本地管理命令完成。
- 数据库每日备份，备份文件权限受限并执行保留策略。

## 11. 故障处理

- 单次同步失败不删除或清空历史数据。
- 网络错误和上游 5xx 使用有限次数指数退避。
- 认证失败仅自动重新登录并重试一次，避免账号锁定。
- 连续认证失败进入“认证待更新”状态，暂停高频登录尝试。
- 上游返回格式变化时保留响应摘要和字段差异，但不记录敏感完整响应。
- 写入和汇总使用数据库事务。
- 不完整分页不替换已有完整统计。
- 应用重启后从数据库恢复调度状态，并立即判断是否需要补采。

## 13. 测试策略

### 13.1 单元测试

- 登录成功、失败和响应缺字段。
- Token 失效后自动重新登录。
- 分页、超时、证书错误和上游错误映射。
- 原始记录去重和更新。
- 跨日、零用量、重复时间和延迟记录。
- 日汇总、变化率、峰值、异常和余额预测。
- OAuth `state`、白名单和会话过期。

### 13.2 集成测试

- 使用脱敏固定响应模拟物业接口。
- 从采集到 SQLite、汇总和 API 的完整数据流。
- 数据库事务失败和恢复。
- Nginx 反向代理及安全响应头。

### 13.3 生产验收

- 连续运行至少 24 小时，每 30 分钟自动同步且无重复记录。
- 同一天的用量和费用与物业小程序明细一致。
- 非白名单微信账号无法获得住户数据。
- Token 失效后自动登录，或准确进入认证待更新状态。
- 手机微信内页面布局和图表正常。
- 服务器重启后服务和调度自动恢复。
- HTTPS 检测通过，公网不暴露调试端口、应用内部端口和数据库。

## 14. 凭证维护

正常情况下，服务器通过账号密码自动登录并续期，不需要微信客户端在线。

如果物业认证机制改变，或账号密码登录不再能够在服务器端完成，则在已授权的隔离环境中重新检查接口。必要时由用户在本机完成证书信任或登录操作，并通过服务器本地管理命令更新凭证。不得在聊天、Git、日志或 H5 页面中传递真实密码与 Token。
